## Findings

### BUG-001: Hidden file inputs are exposed before onboarding is complete

- Severity: major
- Status: confirmed on deployed build; fixed locally, not yet pushed
- Area: Upload gate, accessibility, onboarding
- Environment: Vercel deployment `dpl_HdDPbUnamGF4m4HcT2PGRJko4hYj`, commit `ca54574`
- Reproduction:
  1. Open the deployment through a Vercel share URL.
  2. Stay signed out.
  3. Inspect `input[type="file"]` controls.
- Expected: Real room-photo file inputs should be hidden from visual UI and accessibility tree, disabled, and untabbable until account, project, and photo consent are complete.
- Actual: Two native file inputs exist before sign-in/consent with `display:block`, `disabled:false`, `tabIndex:0`, `aria-hidden:null`, and `pointer-events:auto`.
- Evidence: Browser diagnostics showed both file inputs at 1px by 1px, visible, focusable, enabled, and exposed before sign-in. The visible `Upload photo` button was correctly hidden, but the underlying controls were still reachable.
- Suspected cause: `.file-input` used clipping instead of `display:none`, and the file inputs did not carry `disabled`, `aria-hidden`, or `tabIndex={-1}` gates.
- Suggested fix: Local patch changes `.file-input` to `display:none`, adds `aria-hidden="true"`, `tabIndex={-1}`, and disables file inputs until their visible upload action is allowed.
- Verification after fix: Local `tsc -b`, `vitest run`, and `vite build` pass. Needs push/deploy and deployed browser retest.
