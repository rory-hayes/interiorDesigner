## Findings

### BUG-001: Production CSP blocks Supabase auth, project, and storage requests

- Severity: critical
- Status: confirmed by static config
- Area: production auth and persistence
- Environment: Vercel config in `vercel.json`
- Reproduction:
  1. Configure `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
  2. Deploy current app with `vercel.json`.
  3. Try `Continue with email`, Supabase session restore, project save, or room-photo storage upload.
- Expected: browser can call Supabase Auth, PostgREST, and Storage endpoints.
- Actual: CSP is `connect-src 'self'`, which allows only same-origin fetches. Current client code fetches `${VITE_SUPABASE_URL}/auth/v1/otp`, `/auth/v1/user`, `/rest/v1/projects`, `/rest/v1/room_assets`, and `/storage/v1/object/...`.
- Evidence:
  - `vercel.json` CSP: `connect-src 'self'`.
  - Probe result: `allowsSupabaseConnect=false`.
  - Affected code: `src/lib/onboarding.ts`.
- Suspected cause: Supabase was added after the security header was written for same-origin API only.
- Suggested fix: include the configured Supabase origin in `connect-src`, for example `connect-src 'self' https://<project-ref>.supabase.co`, and add a regression test that asserts Supabase is present when Supabase env vars are expected.
- Verification after fix: deploy with Supabase env vars, run passwordless email request, OAuth callback/session load, project save, and room-photo upload from the browser console/network panel with no CSP violations.

### BUG-002: Required Supabase client env vars are missing from env docs

- Severity: major
- Status: confirmed by repo inspection
- Area: setup and deployment
- Environment: `.env.example`, `README.md`, `docs/integrations.md`
- Reproduction:

  2. Add only `OPENAI_API_KEY` and `OPENAI_IMAGE_MODEL`.
  3. Start or deploy the app.
- Expected: docs list every variable required for the planned production auth/persistence path.
- Actual: `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY` are used by `src/lib/onboarding.ts` but are absent from `.env.example`, `README.md`, and `docs/integrations.md`.
- Evidence:
  - `.env.example` contains only OpenAI variables.
  - `src/lib/onboarding.ts` reads `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
- Suspected cause: implementation and setup docs are out of sync.
- Suggested fix: update `.env.example`, README setup, integrations docs, and Vercel deployment checklist.
- Verification after fix: new developer can configure Supabase without reading source; `isSupabaseConfigured()` becomes true in a deployed build.

### BUG-003: Optional persisted project budget can become `undefined` and poison shopping calculations

- Severity: major
- Status: confirmed by code path
- Area: returning user/project persistence
- Environment: Supabase project row with `budget` null or missing
- Reproduction:
  1. Load a Supabase project row where `budget` is null. The schema allows `budget numeric(10, 2)` without `not null`.
  2. `projectFromSupabaseRow()` normalizes that to `budget: undefined`.
  3. `projectToPreferences()` returns `{ budget: undefined }`.
  4. `updatePreferences(projectToPreferences(latestProject))` merges `budget: undefined` into `ProjectPreferences`.
- Expected: optional onboarding budget should keep the default budget or normalize to a valid number.
- Actual: downstream code expects `preferences.budget` to be a number. `formatCurrency(preferences.budget)`, `calculateCartSummary`, and product affordability checks can show `NaN` or select no products.
- Evidence:
  - `src/lib/onboarding.ts`: budget is optional and can be undefined.
  - `src/lib/share.ts`: `formatCurrency(amount: number)` calls `amount.toLocaleString`.
  - `src/lib/recommendations.ts`: calculations compare against `preferences.budget`.
- Suspected cause: plan made budget optional in onboarding, but app state type and calculations still require a numeric budget.
- Suggested fix: either make project budget non-null with a default in schema/app, or omit `budget` from `projectToPreferences()` when undefined.
- Verification after fix: add a regression test for loading a persisted project without a budget and confirm the drawer/shopping flow uses the default budget.
